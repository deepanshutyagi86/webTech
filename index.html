HTML — HyperText Markup Language
Structure of every web page
+
🧠 Simple Explanation

HTML is the skeleton of a web page. Just like bones give your body shape, HTML gives a page structure. It uses tags (labels in angle brackets) to tell the browser what each piece of content is — a heading, a paragraph, an image.

Basic Document Structure
  html · basic template
<!DOCTYPE html>         <!-- tells browser: this is HTML5 -->
<html>                   <!-- root element: everything goes inside -->
  <head>               <!-- invisible info: title, CSS links, meta -->
    <title>My Page</title>
  </head>
  <body>               <!-- everything the USER SEES goes here -->
    <h1>Hello World!</h1>
    <p>This is a paragraph.</p>
  </body>
</html>
Key Rules
  • Tags come in pairs: <tag> opens, </tag> closes
  • Self-closing tags have no content: <br>, <img>, <hr>
  • HTML is NOT case-sensitive — but always write in lowercase (best practice)
  • Attributes go inside the opening tag: <img src="dog.jpg" alt="Dog">
  • Extra spaces/blank lines in code are ignored by the browser
  • Comments: <!-- this is invisible to users -->

Lists & Tables
ol, ul, dl — table, tr, th, td
+
3 Types of Lists
html · all list types
<!-- 1. ORDERED LIST (numbered) -->
<ol>
  <li>Step One</li>
  <li>Step Two</li>
</ol>

<!-- 2. UNORDERED LIST (bullets) -->
<ul>
  <li>Apple</li>
  <li>Banana</li>

<!-- 3. DEFINITION LIST (terms + meanings) -->
<dl>
  <dt>HTML</dt>          <!-- definition term -->

Tables
Simple Explanation

A table is like a spreadsheet. <table> = the whole thing. <tr> = one row. <th> = header cell (bold). <td> = data cell (normal).

html · table
<table border="1">
  <tr>
    <th>Name</th>     <!-- header cell: bold by default -->
    <th>Age</th>
  </tr>
  <tr>
    <td>Alice</td>    <!-- data cell -->
    <td>21</td>
  </tr>
</table>
  • border — width of border around cells
  • cellpadding — space between cell content and border
  • cellspacing — space between cells
  • colspan — cell spans multiple columns
  • rowspan — cell spans multiple rows
  • Use tables for tabular data only — not for page layout!

Forms — Collecting User Input
form, input, action, method
+
Simple Explanation

A form is like a paper form at a hospital. Users fill in fields, tick boxes, and click Submit. The data gets sent to a server (the action URL) for processing using the method you specify.

html · complete form example
<form action="/submit" method="post">

  <label for="uname">Username:</label>
  <input type="text" id="uname" name="username"
         placeholder="Enter name" required>

  <input type="password" name="pass" required>

  <input type="checkbox" name="agree"> I agree

  <input type="radio" name="gender" value="m"> Male
  <input type="radio" name="gender" value="f"> Female

  <select name="city">
    <option value="delhi">Delhi</option>
    <option value="mumbai">Mumbai</option>
  </select>

  <input type="submit" value="Submit">

</form>
Form Attributes
AttributePurposeValues
actionWhere to send the form dataA URL, e.g. /submit.php
methodHow to send dataGET (visible in URL) or POST (hidden, secure)
nameKey used to read the value on serverAny string
requiredBrowser blocks submit if emptyNo value needed
placeholderHint text inside empty fieldAny string
targetWhere to display response_self, _blank
🔐

GET vs POST: GET puts data in the URL (?user=john) — visible to everyone, bookmarkable. POST hides data in the HTTP body — use for passwords, sensitive data, or large data.

Dynamic HTML (DHTML)
HTML + CSS + JavaScript working together
+
Simple Explanation

DHTML = HTML + CSS + JavaScript combined. It makes pages interactive — responding to clicks, changing content without reloading, animating elements. It's not a new language, just the combination of these three technologies.

  • JavaScript — the brain (adds logic and behaviour)
  • DOM manipulation — JavaScript changes HTML elements on the fly
  • Event handlers — onclick, onmouseover, onkeydown, onchange
  • CSS changes via JS — change styles dynamically after page loads
dhtml · event + dom example
<!-- Event handling -->
<button onclick="alert('Clicked!')">Click Me</button>

// DOM Manipulation
var para = document.createElement("p");
para.textContent = "Dynamically added text!";
document.body.appendChild(para);

CSS — Cascading Style Sheets
Syntax, selectors, properties, 3 ways to add CSS
+
Simple Explanation

If HTML is the skeleton, CSS is the clothes and makeup. CSS controls colors, fonts, sizes, spacing, animations — everything visual. Without CSS, websites are plain text on white background.

CSS Syntax
css · syntax
/* selector { property: value; } */

p { color: blue; font-size: 16px; }    /* element */
.highlight { background: yellow; }         /* class */
#header { font-size: 24px; }              /* ID */
h1, h2, h3 { color: red; }                /* group */
ul li { list-style: square; }             /* descendant */
input[type="text"] { border: 1px solid; }  /* attribute */

The CSS Box Model
Content → Padding → Border → Margin
+
Simple Explanation

Every HTML element is a box. The box has 4 layers from the inside out: Content (the actual text/image) → Padding (cushioning inside the border) → Border (the wall) → Margin (space between this box and others outside).

MARGIN
BORDER
PADDING
CONTENT (text / image)
css · box model example
.box {
  width: 200px;          /* content width */
  padding: 20px;        /* space INSIDE border */
  border: 2px solid black;
  margin: 10px;         /* space OUTSIDE border */
  box-sizing: border-box; /* includes padding+border in width */
}
🧠

Order from center outward: Content → Padding → Border → Margin. Remember: "Can People Bring Milk"

XML — eXtensible Markup Language
Structure, elements, attributes, well-formedness
+
Simple Explanation

XML is like HTML, but you make up your own tags. Its purpose is not to display data — it's to store and transport data between different systems. Think of XML as a universal language that lets computers from different companies exchange information.

xml · employee example
<?xml version="1.0" encoding="UTF-8"?>
<employees>                    <!-- root element -->
  <employee id="1">           <!-- attribute on element -->
    <name>John Doe</name>
    <department>Engineering</department>
    <salary>50000</salary>
  </employee>
</employees>
Well-Formedness Rules (MUST follow)
  • Must have exactly ONE root element
  • All tags must be properly closed
  • Tags must be properly nested (no crossing)
  • Attribute values must be in quotes
  • Tags are case-sensitive — <Name> ≠ <name>
Meta Tags & Character Entities
EntityDisplaysUse When
&lt;<Show < sign in text (otherwise browser reads it as tag)
&gt;>Show > sign in text
&amp;&Show & sign in text
&nbsp;  Non-breaking space (won't collapse)

DTD & XML Schema (XSD)
Defining rules for XML documents
+
Simple Explanation

Both DTD and XSD are rulebooks for XML. They say: "this document must have these tags, in this order, with these data types." If an XML file breaks the rules, it's called invalid. DTD is the old rulebook; XSD is the newer, more powerful one.

FeatureDTDXSD (XML Schema)
SyntaxCustom, non-XML syntaxWritten in XML itself
Data TypesOnly text (#PCDATA)Rich: string, integer, decimal, date...
Namespace SupportNOYES
InheritanceNOYES
Modular DesignLimitedCan import/include other schemas
CompatibilityOlder systemsModern standard (SOAP, Web Services)
🧠

DTD = Old, simple. XSD = New, powerful. Both define rules for an XML file. XSD wins on every feature except simplicity.

dtd · example
<!DOCTYPE employees [
  <!ELEMENT employees (employee*)>
  <!ELEMENT employee (name, department, salary)>
  <!ATTLIST employee id ID #REQUIRED>
  <!ELEMENT name (#PCDATA)>
  <!ELEMENT salary (#PCDATA)>
]>
🌳
DOM & SAX Parsers
Two ways to read XML documents
+
Simple Explanation

DOM = read the entire book first, then answer questions. SAX = read the book sentence by sentence and react as you go. DOM is easy but slow for huge files. SAX is memory-efficient for large XML.

ComparisonDOM ParserSAX Parser
Loads whole file?YES — entire document in memoryNO — sequential, event-based
Memory usageHighLow (great for large files)
Random access?YES — navigate anywhereNO — sequential only
Modifiable?YES — add/delete/edit nodesNO — read-only
Ease of useEasier, intuitive tree APIMore complex (handle events)
Best forSmall-medium files, need navigationLarge files, streaming data
💡

DOM = "Document tree in memory" | SAX = "Sequential events". DOM is like a map you can explore freely. SAX is like listening to a story — you hear it once, in order.

🔒
XHTML & Meta Tags
Strict HTML + XML rules
+
Simple Explanation

XHTML = HTML that follows XML's strict rules. All the lazy habits HTML allows (uppercase tags, unclosed tags) are forbidden in XHTML.

  • All tags must be lowercase
  • All tags must be closed — even <br /> not <br>
  • Attribute values must be in quotes
  • Must have a single root element
  • Must include a DOCTYPE declaration
Meta Tags (inside <head>)
html · meta tags
<meta charset="UTF-8">                          <!-- character encoding -->
<meta name="description" content="My page">    <!-- shown in Google results -->
<meta name="keywords" content="web, html">
<meta name="author" content="Your Name">
